# Git 규칙 (항상 로드)

## 커밋
- 제목: `[타입] 한국어 요약` (~30자, 마침표 없음, "~ 추가/수정" 명사형)
- 타입: feat(새 기능) · fix(버그) · docs(문서만) · refactor(동작 같고 구조만) · test(테스트·eval만) · chore(설정·의존성)
- 본문: 무엇을, 왜 바꿨는지 `-` 목록으로
- 커밋 1개 = 논리적 변경 1개. 코드·테스트·문서는 나눠 커밋한다
- 리뷰 Unit이 사용자에게 승인("OK")된 뒤에만 커밋한다

## 브랜치·푸시
- 로드맵 Step마다 최신 main에서 `step/<번호>-<이름>` 브랜치를 만든다
- 푸시는 Step이 끝났을 때 1번: `git push -u origin step/...`
- 린트·테스트가 통과해야만 푸시한다
- merge는 사용자가 PR에서 리뷰 후 직접 한다

## PR 넘길 때 (/ship 보고에 항상 포함, 붙여넣기용 코드 블록으로)
- PR 제목: `[Step N] 한국어 요약` 예) `[Step 1] 개발 규칙 문서와 보안 설정`
- PR 설명: 무엇을 / 확인(린트·테스트 결과) / 리뷰 기록(Q&A·결정)
- Merge 커밋 제목: `[merge] Step N 한국어 요약 (#PR번호)` — GitHub "Merge pull request" 누른 뒤 제목 칸에 입력
- Merge 커밋 설명: 포함된 커밋 제목 목록

## 금지
- force push, `--no-verify`, main에 직접 커밋·푸시
- `.env` 커밋, 테스트 실패 상태로 커밋
