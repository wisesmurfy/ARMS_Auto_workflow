# ADR-0005: 모듈 A를 웹사이트로 제공한다 (FastAPI + HTML, Vercel)

- 상태: Accepted
- 날짜: 2026-10-29

## 배경
- 승인된 설계(`docs/design/v1-plan.md`)에서 v1의 완성 형태는 터미널 실행(CLI, `uv run evidos "주제"`)이었다
- 사용자는 주소로 접속해 주제를 넣고, 구성안 3개(각 Part 1→2→3)를 시각적으로 비교한 뒤 1개를 고르는 웹사이트를 원한다.
  범위는 모듈 A까지다(PubMed 검색 전)
- 후보는 두 가지였다
  - Streamlit + Streamlit Cloud: 파이썬만 쓰지만 화면 자유도가 낮고 내 도메인을 연결하기 어렵다
  - FastAPI + HTML + Vercel: 화면을 자유롭게 만들 수 있고 도메인 연결이 쉽지만, HTML·CSS·JS를 추가로 리뷰해야 한다
- Vercel은 서버리스다. 요청이 올 때만 잠깐 실행되므로 서버에 저장한 파일이 남지 않고, 함수 실행 시간에 제한이 있다

## 결정
- 웹 = FastAPI(파이썬 API) + HTML 화면이고, Vercel에 배포한다. CLI 대신 웹이 A3 Gate(사람 선택)의 입구가 된다
- 순서는 여전히 `pipeline.py`가 정한다(ADR-0001 유지). 웹은 pipeline을 호출하고 결과를 보여 주기만 한다
- 고른 안은 브라우저에서 `selected_option.json`으로 내려받는다. 서버 저장(데이터베이스)은 v1에서 하지 않는다
- 접근 제한(공유 비밀번호 등)을 반드시 둔다. 공개 주소로 API 크레딧이 소모되는 것을 막기 위해서다
- 로드맵 변경(Step 5부터): 5 A3 + pipeline + API → 6 웹 화면 → 7 Vercel 배포 → 8 eval → 9 README

## 결과
- 좋은 점: 설치 없이 팀원이 주소로 바로 쓸 수 있다. Part 흐름을 그림처럼 보여 줄 수 있다. 내 도메인을 연결할 수 있다
- 감수할 점: HTML·CSS·JS 리뷰가 늘어난다(Unit 2~3개). 선택 기록이 서버에 남지 않는다
- 확인할 것: A1+A2 호출 시간이 Vercel 무료 요금제의 함수 실행 시간 한도 안에 들어오는지 (Step 7에서 공식 문서로 확인)
- 다시 볼 조건: 선택 기록 보관이나 로그인이 필요해지면 Supabase 도입을 새 ADR로 검토한다.
  실행 시간 한도를 넘으면 호스팅을 다시 검토한다
